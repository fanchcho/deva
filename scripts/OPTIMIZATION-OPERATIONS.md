# Resource and persistence controls

- `DEVA_AUDIT_DAYS` (default 30), `DEVA_AUDIT_BYTES` (default 268435456): retention applies only to new `audit/users/<id>/managed-v1/` files. Legacy logs remain unchanged, readable and outside the quota. Body text and positional secret values are not audited. Managed files roll at 1 MiB and daily boundaries. Audit IO failures surface as errors.
- `DEVA_SESSION_CACHE_COUNT` (default 20), `DEVA_SESSION_CACHE_BYTES` (default 268435456): budgets use serialized size × 2 as an estimate. Active/current/unsaved sessions are pinned; pinned entries may exceed the budget. Reloaded sessions are read from disk.
- Shared config writers acquire `<file>.lock`, compare the loaded revision, write a unique 0600 temporary file, fsync and rename. Conflicts require reload/retry. Both the lock and its `.recovery` guard recover only when same-host process probing confirms death and the last heartbeat is older than 300 seconds. Live/reused PIDs, permission uncertainty, foreign hosts and backwards clock readings fail closed. Recovery decisions are fsynced to `<file>.lock-audit.jsonl` before removal.
- Guard recovery elects one successor using atomic no-overwrite hard links under `<file>.lock-audit/`. These immutable token-generation records are **persistent arbitration/audit data, not temporary files**. Do not delete, rotate or garbage-collect this directory while any cooperating writer may run: deleting a record permits an old contender to win the same generation again (ABA). They grow by one small record per recovery attempt that wins an election, not per ordinary write. Dead successor generations can be followed after the same death/age checks. No automatic pruning is provided. A denied claimant that is still alive remains a conservative liveness barrier; do not force recovery based only on age.
- The protocol assumes a coherent local filesystem supporting atomic exclusive hard links within one directory tree. Unsupported links or uncertain process metadata fail without modifying the guarded configuration. Windows/macOS native filesystem and process identity behavior remain unexecuted in this Linux environment; POSIX mode is not a Windows ACL guarantee.
- Session indexes flush after 200 ms and at graceful process exit. A dirty marker causes rebuild after an interrupted save. Disk-full errors leave the marker and session data for retry.
- History snapshots retain short user-turn labels for navigation and load earlier full turns on demand. A cursor hash covers the old prefix, allowing new streaming output without invalidating older pages. Rewritten old history invalidates the cursor. GUI regressions must cover jump/delete/rewind while streaming and errors during page fetch.
- Media sweep starts 10 seconds after the window is shown (Web: after backend initialization) and yields between directory entries. IO is serial. Reference-read failures abort deletion. Incremental persistent blob reference indexes are deliberately not introduced without a migration/recovery design.
